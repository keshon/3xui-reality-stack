Bare VPS to Four Lanes

Seven phases from an empty Debian box to four working transports, one account per person, and a real website as cover. Everything after phase 5 is automatic — the work is in getting phases 0–4 right.

What you end up with

0Registrar
+ DNS

Point three names at the server

Put the zone on Cloudflare, then create an API token scoped to Zone → DNS → Edit for that one zone. Add three A records to the server's IP.

RecordBecomesWho sees it
wwwPUBLIC_DOMAINthe only hostname your users touch
opsPANEL_DOMAINyou — panel + subscriptions
toolsTOOLS_DOMAINyou — dashboard
Grey cloud, not orange Set proxy status to DNS only. A CDN proxy terminates TLS and won't forward UDP — orange cloud breaks all four lanes at once, and the failure looks like a config bug.

Pick a plausible hostname. A generated-looking name like a7f2-x9k is itself a signal.

1Provider
panel

Open the ports upstream

A fresh Debian or Ubuntu box with root. Before you touch it, open these in your provider's firewall:

22/tcp   80/tcp   443/tcp   443/udp   8443/tcp
The one everyone misses Most providers have a firewall in their control panel that's separate from ufw, and 443/udp is usually closed by default. Hysteria2 then fails silently — no error in any log, on either side.

3Server
editor

Fill in .env

Eight values. Everything else can stay blank — the installer generates it and writes it back into the file.

BASE_DOMAIN=example.com
PUBLIC_DOMAIN=www.example.com
PANEL_DOMAIN=ops.example.com
TOOLS_DOMAIN=tools.example.com
CERT_BASENAME=example.com
LETSENCRYPT_EMAIL=you@example.com
CF_DNS_API_TOKEN=<from phase 0>
USERS=alice,bob,carol
Generated for you PANEL_PATH, SUB_PATH, JSON_PATH, PANEL_USER, PANEL_PASS, DASHBOARD_AUTH. Leave them empty and they're created on first run and printed once.

One account per name in USERS, attached to every lane, with a single subscription URL each.

4Server
files

Replace the decoy site

Put something real in decoy/site/. The shipped pages are placeholder prose.

This is load-bearing, not decoration The decoy is what Reality's fallback serves, what an active prober sees, what Hysteria2 masquerades as, and what unknown-host and bare-IP scans get. A site that reads as filler undoes the rest of the design.

A static export of anything you actually have works. What matters is that it doesn't look synthetic, and that it stops changing once deployed.

5Server
shell

Run the installer

sudo ./install.sh

It's idempotent — re-run it any time you edit .env. In order, it:

  • generates missing secrets and writes them back to .env
  • checks your three names actually resolve here before attempting ACME
  • installs Docker, applies BBR + fq and socket tuning, opens ufw
  • brings up Traefik, the decoy, and 3x-ui; waits for the wildcard certificate
  • sets the panel base path, credentials, and public subscription URLs
  • generates a Reality keypair and provisions all four lanes
  • collapses per-lane clients into one account per person
  • verifies, then prints the subscription URLs
Takes a few minutes Most of it is waiting for DNS-01 propagation and the certificate. If it stops, it tells you which check failed rather than continuing into a broken state.
6Anywhere

Verify the cover story

The installer runs these, but this is the one worth knowing by heart:

openssl s_client -connect <IP>:443 -servername www.example.com </dev/null \
  2>/dev/null | openssl x509 -noout -subject -issuer

It must return your own Let's Encrypt certificate. If it ever returns someone else's — a CDN's, a search engine's — then target and serverNames have drifted apart, and the server is identifiable in a single connection.

✓curl -sI https://www.example.com/ returns 200 with your real page
✓a bare-IP scan gets a valid cert, not the proxy's self-signed default
✓dig +short agrees with the IP clients dial
✓docker logs 3x-ui has no Failed to start
7Your
people

Hand out one URL each

Each person gets a single subscription URL carrying all four lanes, which updates itself when you change an inbound. Their client — Happ, Hiddify, v2rayN — picks between lanes with urltest.

LaneClient setting
Trojan / httpupgrademux on — without it every connection pays a full TLS handshake
VLESS + Visionmux off — it defeats the record shaping Vision exists for
MTProtothe tg://proxy?… link goes straight into Telegram

Test with one person for a day before handing it to everyone. If something's wrong you want a clean signal, not five people reporting different symptoms.

Network diagnosticsbash scripts/triage.sh
amneziawg is safe — and worth a look The panel offers it, and it does not go through Xray: 3x-ui embeds amnezia-vpn/amneziawg-go and runs instances itself, so an amneziawg inbound never reaches the Xray config and cannot stop the other lanes. Configure it through the panel UI (the API schema is undocumented), and give the container NET_ADMIN and /dev/net/tun. Obfuscated WireGuard is the version worth having — plain WG has a fixed-size handshake that is trivially fingerprinted.
What the panel can break Editing the hysteria inbound through the web UI silently drops a required field, after which Xray refuses to start and every lane stops — the decoy site included. The panel accepts configurations Xray cannot execute, and it is a single Xray process. Read docs/gotchas.md before editing anything through the web UI.
Phases 0–4 are yours; 5–7 are the installer's. Almost every failure traces back to DNS not being ready, the provider firewall, or the decoy site.
